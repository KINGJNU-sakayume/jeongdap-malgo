# 퍼즐 작성 형식

- 상태: 초안 v0.1
- 쓰임: 새 퍼즐을 만들 때 이 순서대로 쓴다. 퍼즐 하나 = 문서 하나(`docs/puzzles/p02-name.md`) + 코드 하나(`src/puzzles/p02.ts`) + 대사 하나(`content/lines/p02.md`).
- 정본: 판정·업적은 `docs/puzzles/`, 대사 텍스트는 `content/lines/`. 코드는 둘을 따른다.
- 관련: `spec/data-format.md`(스키마), `narrator-bible.md`(말투)
- 표기: 전부 **[추측]**(설계안).

---

## 1. 작성 순서

1. **물건을 고른다.** 서식 세계에 있는 평범한 물건(번호표, 서명란, 도장). 설명 없이 누구나 정답을 아는 것.
2. **정답을 한 문장으로 쓴다.** 두 문장이 필요하면 퍼즐이 너무 어렵다.
3. **틀림을 유형별로 하나씩 브레인스토밍한다**(3장). 최소 4개, 권장 5~6개.
4. **판정 조건을 숫자로 쓴다.** "칸 밖" → "잉크 중심이 확인란 사각형 밖".
5. **충돌을 검사한다.** 한 상태가 두 틀림에 걸리면 순서를 정하거나 복합 틀림으로 만든다.
6. **예시 상태를 쓴다.** 결과마다 하나 이상. 이게 곧 테스트다.
7. **대사 요지를 쓴다.** 한 줄씩. 펀치만.
8. **대사를 쓴다.** 진입 → 정답 → 틀림(1회/2회/3회+) → 단계 변주 → 이벤트 → 기타.
9. **소리 내 읽는다.** 걸리는 비트를 고친다.
10. **체크리스트(6장)를 통과시킨다.**

---

## 2. 좋은 퍼즐의 조건

- **5초 안에 정답이 보인다.** 어려운 건 정답이 아니라 '틀리는 방법 찾기'여야 한다.
- **입력 위젯은 고정 목록에서만** (`spec/data-format.md` 2장). 새 위젯이 필요하면 퍼즐을 바꾼다.
- **모바일에서 한 손으로 된다.** 두 손가락 제스처, 우클릭, 호버, 키보드 단축키에 기대지 않는다.
- **화면 하나.** 스크롤은 약관처럼 스크롤 자체가 소재일 때만.
- **지시문은 서식체 한 줄 + 큰 동사.** 예: 작은 글씨 「확인란에 도장을 찍으시오」, 큰 글씨 **찍으시오**. (조사 2-4: WarioWare의 동사 지시)

## 3. 틀림 유형 다섯 가지

각 퍼즐은 **최소 세 유형**을 포함한다. 한 유형만 있으면 같은 농담이 반복된다.

| 유형 | 정의 | 발견 난이도 | 예 |
|---|---|---|---|
| **실** 실수형 | 누구나 손이 미끄러져서 낼 수 있음 | 낮음 | 칸 밖, 하나만 틀린 정렬 |
| **문** 문자형 | 지시문·예시를 문자 그대로 따름 | 중간 | 홍길동, '이름', 역순 정렬 |
| **과** 과잉형 | 너무 많이, 세게, 크게, 오래 | 낮음 | 연타, 낙서, 장문 |
| **탈** 탈선형 | 엉뚱한 대상에 함 | 높음 | 주무관 이마에 도장, 지시문 끌기 |
| **방** 방치형 | 안 하거나 그대로 둠 | 중간 | 빈칸, 0개 선택, 오래 기다리기 |

**배합 원칙**
- 실수형 하나는 반드시 넣는다. 정답을 노리다 우연히 틀린 플레이어에게도 반응이 있어야 한다.
- 탈선형 하나는 넣는다. '모든 틀림 찾기'의 마지막 보상은 대개 탈선형이다.
- 화면 밖 요소(화자 아이콘, 지시문, 서식 여백)를 조작 대상으로 쓰는 탈선형은 장마다 1개 정도. (조사 2-2, 2-3)
- 복합 틀림은 '진입 대사에서 조건 셋을 나열한 퍼즐'에만. 3의 법칙 장치. (예: P12 삼관왕)

## 5. 대사 작성 형식 (D-003: `content/lines/pNN.md`에 이 형식으로 쓴다)

```
# p02 성명

> 이 줄처럼 '>'로 시작하는 줄은 작가 메모. 파서가 무시한다.

## p02.hong

홍길동 님이시군요. //
아, 예시를 그대로 쓰셨구나.
괜찮아요, 많이들 그러세요.
진짜 많이들 그러세요.

@repeat 2
홍길동 님 또 오셨네요.
반갑습니다. 반갑지는 않고요.

@repeat 3
아버지를 아버지라 부르지 못하고— //
아닙니다. 본인 성함 적어 주세요.

@stage 3-5 @repeat 1
홍길동. 네. 홍길동.
오늘 홍길동만 몇 번째인지 세다가 그만뒀어요.
```

**문법**
- `# ...`: 파일 제목. 무시.
- `## 결과ID`: 결과 하나의 시작. 진입 대사는 `## pNN.@enter`. 화자 공용은 `## @stage-up.1` 같은 `@`로 시작하는 ID.
- **묶음** = 빈 줄로 구분되는 줄들. 묶음 첫 줄이 `@`로 시작하면 조건 줄, 아니면 조건 없는 기본 변주.
- 조건 줄: `@stage a-b`, `@repeat 1|2|3`, `@if 결과ID`, `@todo`를 공백으로 이어 쓴다. 한 묶음에 조건 줄은 하나.
- 나머지 줄 = 비트 하나씩. 줄 끝 ` //`(앞에 공백) = 긴 정지. 표시 없음 = 짧은 정지. 마지막 비트의 정지 표시는 무시.
- 한 결과 안에 기본 변주가 정확히 하나 있어야 한다.
- 같은 조건 조합의 묶음이 둘 이상이면 `data-format.md` 6-2의 결정적 선택으로 하나를 고른다(같은 상황 대사의 교대용).
- `{name}` 외 중괄호 금지.

### 대사 분량 기준 (1차 목표)
| 결과 종류 | 기본 | 반복 | 단계 변주 |
|---|---|---|---|
| 진입 | 1 | - | S0, S2, S4 정도 3종 |
| 정답 | 1 | - | 2~3종 |
| 틀림 | 1 | 2회, 3회+ | 필요한 것만 (장 상한을 넘는 단계는 재방문용) |
| 이벤트 | 1 | - | - |
| 기타 | 1 | - | - |

퍼즐 하나 ≈ 25~40비트. 15개 ≈ 400~600비트. **[추측]**

## 6. 체크리스트

퍼즐을 '대사 완료'로 올리기 전에 전부 확인한다.

**구조**
- [ ] 정답이 5초 안에 보인다
- [ ] 틀림 + 이벤트가 4개 이상
- [ ] 틀림 유형이 3가지 이상, 실수형과 탈선형이 각각 하나 이상
- [ ] 마지막 규칙이 기타 틀림
- [ ] 모든 결과에 예시 상태가 있다
- [ ] 충돌 메모를 썼다
- [ ] 모바일 한 손으로 모든 틀림을 낼 수 있다
- [ ] 원시 입력(이름·비밀번호·자유 입력)을 저장하지 않는다

**대사**
- [ ] 모든 결과에 기본 변주가 있다
- [ ] 반복 대사가 1회 → 2회(짧게) → 3회+(비틀기)로 간다
- [ ] 펀치가 마지막 비트에 있다. 그 뒤에 설명이 없다
- [ ] 비트 하나가 60자 이하
- [ ] 소리 내 읽었다
- [ ] 번역투가 없다 (가능합니다, ~에 대해, 그것은)
- [ ] 화자가 이기는 대사보다 지는 대사가 많다
- [ ] 이 장의 단계 상한을 넘는 말투가 기본 변주에 없다
- [ ] 금지어가 없다 (`narrator-bible.md` 7장)
- [ ] 콜백은 1~2개 이하

**업적**
- [ ] 틀림·이벤트마다 업적 이름과 설명이 있다
- [ ] 업적 이름은 6자 안팎, 설명은 공문서체 한 줄("~함", "~됨")
- [ ] 업적 이름이 대사의 펀치를 미리 말해 버리지 않는다

---

## 7. 업적 이름 짓기

- **이름**: 짧은 명사구. 대사의 펀치와 겹치지 않게, 그러나 보면 그 장면이 떠오르게. 예: 「무명씨」 「물구나무」 「핀셋 해제」.
- **설명**: 공문서체 처리 결과. 예: "성명란을 비워 둔 채 제출함", "전체 동의 후 담당자 퇴근 기원만 해제함".
- **발견 전 표시**: "??? 반려 사유 미확인". 서식별로 묶지 않고 목록 끝에 한꺼번에 둔다(D-002).

## 8. 예: P02 결과 표 (작성 예시)

| ID | 종류 | 유형 | 조건 | 예시 상태 | 반응 요지 | 업적 |
|---|---|---|---|---|---|---|
| p02.empty | 틀림 | 방 | 공백만 | `''` | 칸이 비어 있어요 | 무명씨 / 성명란을 비워 둔 채 제출함 |
| p02.hong | 틀림 | 문 | 정규화 후 `홍길동` | `'홍길동'` | 예시를 그대로 | 예시와 같음 / 서식 예시를 그대로 적음 |
| p02.literal | 틀림 | 문 | `이름`·`성명`·`성함` | `'이름'` | 정확하긴 합니다 | 문자 그대로 / 성명란에 '이름'이라고 적음 |
| p02.clerk | 틀림 | 탈 | `도한결` | `'도한결'` | 제 이름인데요 | 대리인 아님 / 담당 주무관 이름으로 신청함 |
| p02.long | 틀림 | 과 | 30자 이상 | (긴 문자열) | 김수한무 | 삼천갑자 / 칸보다 긴 이름을 적음 |
| p02.robot | 틀림 | 탈 | 한글·영문 없음 | `'1234'` | 로봇이세요? | 사람 확인 필요 / 사람 이름이 아닌 것을 적음 |
| p02.ok | 정답 | - | 한글·영문 2~10자 | `'김민지'` | {name} 님 확인 | - |
| p02.other | 기타 | - | 항상 | `'김1'` | 뭐라고 해야 할지 | - |

**충돌 메모**: `도한결`은 정답 조건(한글 2~10자)에도 맞으므로 정답보다 위에 둔다. 30자 이상 한글은 정답 조건(10자 이하)에 안 걸리므로 순서 무관하지만, 읽기 쉽게 틀림을 모두 정답 위에 둔다.
