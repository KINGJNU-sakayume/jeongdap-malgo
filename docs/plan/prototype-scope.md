## 1. 목표: 검증할 가설 다섯

| # | 가설 | 성공 기준 |
|---|---|---|
| H1 | 사람들은 정답을 맞힌 뒤에도 **자발적으로** 틀리러 돌아간다 | 테스터 3명 중 2명 이상이 정답 후 같은 퍼즐을 다시 연다 |
| H2 | 화자가 '너무 일찍 화난다'고 느끼지 않는다 | "화자가 언제부터 짜증 났나?"에 첫 퍼즐이라고 답한 사람이 없다 |
| H3 | 기록 재계산 + 대사 파일 방식이 1인 개발 속도를 올린다 | 퍼즐 하나 추가(판정+대사 연결)에 반나절 이하 |
| H4 | 텍스트 비트와 정지만으로 코미디 타이밍이 산다 | 웃음이 비트 직후에 나온다(관찰 기록) |
| H5 | 모바일에서 모든 틀림을 낼 수 있다 | 5개 퍼즐 × 모든 결과를 폰에서 재현 |

## 3. 범위 안 / 밖

**안**
- 판정 엔진(규칙 평가, `also`, 기타 틀림, 이벤트 규칙)
- 기록 저장/불러오기(localStorage `jdm:v1:log`, try/catch, 메모리 폴백)
- 기록 기반 계산: found, repeatIndex, stage, 업적(자동 생성 + 메타 2개: 「반려 사유 수집가」 n=10으로 축소, 「알고 그랬죠」)
- 대사 파서(`content/lines/*.md`) + 대사 선택기(콜백 > 반복 > 단계 > 기본, 결정적 선택)
- 비트 출력(정지, 탭으로 완성/넘기기, 끼어들기)
- 대기석: 서식 카드 5장(반려 도장 겹치기, 금색 「전수 확인」 인장), 수집판(D-002 규칙)
- 효과음 2개(`click`, `stamp`) Web Audio 합성, 음소거 토글(D-004)
- 디버그 패널(`?debug` 쿼리일 때만): 단계 강제, 기록 초기화, 기록 내보내기(JSON 복사), 결과 강제 발생, 현재 퍼즐 상태 보기
- Vitest: 판정 예시·반례·도달, 대사 파서, 대사 누락, 업적 연결, 금지어, 비트 길이, 로그 계산
- GitHub Pages 배포

**밖**
- 장 구성, 4장 협상, 엔딩, P16
- 아트(색과 단순한 도형, 서식 느낌의 타이포만), 음악
- 게스트 화자
- 나머지 10개 퍼즐

| D4 | 비트 출력 컴포넌트, 디버그 패널, P02 연결 | P02 모든 결과를 화면에서 재현 |

## 5. 플레이테스트 진행 (조사 3-3)

1. 설명 없이 링크만 준다. "편하게 해 보세요."
2. 옆에서 보며 비트마다 웃음/무반응/불쾌를 기록.
3. 끝나고 질문 3개:
   - 정답 맞힌 뒤에 왜 다시 열었어요? (또는 왜 안 열었어요?)
   - 화자가 언제부터 짜증 난 것 같았어요?
   - 화자가 싫었던 순간이 있었어요?
4. 디버그 내보내기로 로그를 받아 결과별 발견 순서를 본다.

## 6. 끝나고 결정할 것
- 단계 임계값(D<3, <10 …) — 퍼즐 5개 기준으로는 `D<2, <5, <9, <14, <20`로 축소해 쓴다(`src/config.ts`에 둠)
- 비트 정지 시간
- 금색 인장만으로 '다 찾았다' 신호가 충분한지
- 나머지 10개 퍼즐 순서
